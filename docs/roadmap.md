# 路线图与已知缺口

## 已完成

- P0：MV/MZ 解密 + 解析 → IR；Electron CDP 驱动事件解释器（stub 运行时验证机制）
- P1：静态 MVP —— 12 检查器 + HTML 报告 + CLI scan
- P2：生命周期 facts + 条件恒假/死逻辑 + 传送软锁 + 可达性
- P3：场景 DSL + 校验闸门 + 执行器 + 覆盖计数 + fuzz + 求解器补测 + golden 截图 diff
- P4：时效性三分类 + 机械重链 + 项目库（SQLite）+ CLI maintain
- P6（部分）：插件加载器（用户自写 checker）

## 已知缺口（按优先级）

1. **真实 MV/MZ 引擎端到端验证**（最高优先）：✅ 已完成——解释器级（命令语义/传送等待）与场景级（进入地图场景、对话触发与确认、存档往返）全部在开发者自有工程上验证（`RM_REAL_PROJECT` 环境变量门控，引擎文件不进仓库）。**验证抓出并修正三处保真 bug**：201 传送真实格式 `[mode, mapId, x, y, dir, fade]`、122 变量常量在 `params[4]`、快照稀疏数组规范化。剩余可深化项：对话选项导航（choose）、移动路径模拟（walk 目前直接定位）。
2. **条件可满足性（有界抽象执行）**：当前"条件恒假"覆盖"读未写"场景；带事件重入语义的全量抽象执行未做（复杂度收益比不划算，暂缓）。
3. **AI 层（P5）**：✅ 已实现核心链路 —— provider 抽象（Ollama/任意 OpenAI 兼容）、NL→DSL 场景生成（校验闸门循环）、失败轨迹→bug 报告翻译。已用本地 `qwen3:1.7b` 真实验证（一次通过校验闸门）。**视觉抽检**（截图→异常评分）未做：需要视觉模型（llava/qwen-vl），当前机器内存 3GB 空闲不够跑视觉模型。
4. **增量分析**：当前扫描为全量（解析速度对典型工程足够快）；文件 diff → 脏 facts 传播的增量框架未做。
5. **RGSS（VX Ace/XP/VX）与 2k/2k3 适配器**：IR 已为多引擎设计；RGSS 动态运行依赖 mkxp-z，2k3 依赖 EasyRPG Player。静态分析部分（引用/生命周期/软锁）对这两个引擎的数据格式可直接移植。
6. **开关/变量的个体粒度重链**：✅ 开关已实现（写入签名哈希 + 唯一匹配迁移）；变量同理但暂未做（结构相同，按需补）。
7. **部署产物验收模式**（分发版测试）：✅ 加密产物（.rpgmvp/.rpgmvo）解密映射 + `deploy` 命令（大小写专项/加密解析/字体检查）；编辑器真实部署产物的验证仍建议做一次。
8. **插件分发渠道**：✅ 文件级分发约定（单文件 ES 模块 + loadCheckersFromDir + 示例插件 + 文档）；无发布平台（对社区场景文件分享最直接）。

## 不做的事（定位边界）

- 不提供游戏内容提取/破解他人游戏的能力（定位声明见 README）
- 不做叙事/审美判断（AI 可"标记可疑"，确定性工具不"判定"）
- 不承诺"覆盖 Unity/UE"：IR 只服务数据驱动 RPG 引擎；编译型引擎是另一套技术
